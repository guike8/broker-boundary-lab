# Reporting a finding

Include the affected artifact digest, application and CLI versions, the boundary being tested, a synthetic reproduction, expected behavior, observed behavior, and the limits of the evidence. Keep real account identifiers, tokens, conversation data, and production captures out of public issues.

A static inspection lead is not a reproduced vulnerability. Tests against an extracted pure function establish that function's behavior with the supplied mocks, not live authorization for every route in the application.

For a vulnerability in Codex or another upstream product, follow that vendor's current security-reporting process before publishing details that would enable exploitation. OpenAI's policy is available at [Coordinated vulnerability disclosure](https://openai.com/policies/coordinated-vulnerability-disclosure-policy/). A private upstream report and a public tooling release are separate actions.

For defects in this repository's tools, open an issue with synthetic inputs and the smallest reproduction. The publication checker reports locations and categories without echoing matched credential contents.
